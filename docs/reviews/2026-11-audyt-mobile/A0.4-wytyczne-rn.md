## 0. Podsumowanie i rekomendacja (D7)

**Rekomendacja: zostajemy przy paradygmacie „Tailwind v4 przez `className`”, ale zmieniamy silnik domyślny
z NativeWind v5 preview na Uniwind (wersja darmowa, MIT). Warunek: spike na Expo SDK 58 (§6, pkt 2). NativeWind v5
zostaje ścieżką powrotną po wydaniu stabilnej wersji zgodnej z bieżącym SDK.** Niezależnie od D7 trzeba od razu wycofać
z builderów pin `nativewind@5.0.0-preview.2` + `react-native-css@0.0.0-nightly.5ce6396`.

Uzasadnienie:
1. **Obecny stan szablonu jest zepsuty, a nie tylko „osierocony”.** `expo-tailwind-setup` (l. 25) i
   `feature-builder-mobile-ui.md` (l. 71: „pinuj exact `5.0.0-preview.2`”) instalują ten sam nightly `react-native-css`,
   który Expo uznało za przyczynę błędów instalacji i crashy Metro na SDK 54–57. Zgłoszenie ENG-25794 zebrało 17 rozmów
   z feedbacku ([PR #174](https://github.com/expo/skills/pull/174)). Maintainer NativeWind pisał wprost: „Nightlies go
   stale … and fail install with ERESOLVE on newer Expo SDKs” ([PR #101](https://github.com/expo/skills/pull/101)).
2. **NativeWind nie ma dziś wersji, która jednocześnie jest stabilna, ma Tailwind v4 i jest testowana na SDK 58.**
   - Stabilne `latest` to 4.2.7 na Tailwind v3 ([npm](https://www.npmjs.com/package/nativewind),
     [llms.txt](https://www.nativewind.dev/llms.txt)), czyli konfiguracja w `tailwind.config.js`. Web ma Tailwind v4
     CSS-first.
   - v5 jest w RC: `5.0.0-rc.1` z 2026-11-02, po 13 miesiącach preview (`5.0.0-preview.0` wyszło 2025-09-24, według
     metadanych npm). RC celuje dokładnie w Expo 57.0.22 / RN 0.86.3 / Reanimated 4.5.1, a „older Expo SDKs still need
     separate compatibility verification” ([release rc.0](https://github.com/nativewind/nativewind/releases/tag/5.0.0-rc.0),
     [rc.1](https://github.com/nativewind/nativewind/releases/tag/5.0.0-rc.1)).
   - Bieżący SDK to 58 (RN 0.88.1, Reanimated 4.7.1, wydany 2026-10-15)
     ([changelog](https://expo.dev/changelog/sdk-58),
     [bundledNativeModules sdk-58](https://github.com/expo/expo/blob/sdk-58/packages/expo/bundledNativeModules.json)).
3. **Uniwind jest dokładnie w modelu, którego Expo zażądało: wytyczne dla agentów utrzymuje zespół biblioteki.**
   Ma oficjalny skill `uniwind` oraz `migrate-nativewind-to-uniwind`, instalowane przez `npx skills add uni-stack/uniwind`
   ([docs/skills](https://docs.uniwind.dev/skills.md), [SKILL.md](https://github.com/uni-stack/uniwind/blob/main/skills/uniwind/SKILL.md)).
   NativeWind ma tylko skille migracyjne v4→v5 i preview→RC, bez skilla „jak pisać”
   ([skills/](https://github.com/nativewind/nativewind/tree/main/skills)).
4. **Uniwind jest stabilny na Tailwind v4 i jest w oficjalnych materiałach Expo.** Wersja 1.13.1 z 2026-10-28,
   peer `tailwindcss >=4`, `react-native >=0.81` ([npm](https://www.npmjs.com/package/uniwind)). Przewodnik Expo
   wymienia NativeWind i Uniwind równorzędnie ([docs.expo.dev/guides/tailwind](https://docs.expo.dev/guides/tailwind/)).
   `expo/examples` ma `with-router-uniwind`
   ([katalog w expo/skills](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-examples/references/catalog.md)).
   Błędy z RN 0.88 zamknięto w 2–3 dni od zgłoszenia ([#737](https://github.com/uni-stack/uniwind/issues/737),
   [#736](https://github.com/uni-stack/uniwind/issues/736)).
5. **Spójność z webem i kod pisany przez agentów.** Dzięki `className` + Tailwind v4 (`@theme` w `global.css`) tokeny
   i nawyki z `tailwind-react-guidelines` przenoszą się 1:1. `react-native-reusables` (shadcn dla RN) deklaruje
   obsługę NativeWind i Uniwind ([repo](https://github.com/founded-labs/react-native-reusables)).

Ryzyka rekomendacji:

|---|---|---|

Alternatywa zachowawcza, czyli zostajemy przy NativeWind: przejście z preview na `5.0.0-rc.1` + `react-native-css@3.1.0-rc.1`

utrzymywać samemu. NativeWind 4.2.7 działa na SDK 58 z ostrzeżeniami ([#1881](https://github.com/nativewind/nativewind/issues/1881)),
ale wraca do Tailwind v3, czyli rozjeżdża się z webem.

## 1. Dlaczego Expo usunęło skill NativeWind

- **PR [#151](https://github.com/expo/skills/pull/151)** „[expo] remove NativeWind skill”, merge 2026-08-31, commit
  `a8f0b6c`. Uzasadnienie w opisie: „NativeWind-specific agent guidance should be owned and maintained by the NativeWind
  team.” Usunięto skill, metadane Codexa i wpisy w katalogach, a pluginy podbito 1.10.1 → 1.10.2.
- **Dyskusja w #151:**
  - Doug Lowder (review 2026-08-28): „Since there has been no activity on the NativeWind side, let's move forward …
    Once a new NativeWind v5 skill becomes available, we can create a new PR to reference it.”
  - Kudo (2026-08-31): „may look back to add nativewind as a reference (rather than skill) later.”
  - zvadaadam: usunięcie „solves the reported nativewind problem in ENG-25794”.
- **PR [#101](https://github.com/expo/skills/pull/101)** (zamknięty). Maintainer NativeWind (danstepanov) poprawiał skill
  do oficjalnej instalacji v5:
  - `react-native-css@latest` zamiast nightly;
  - polyfill `className` zamiast wymaganych wrapperów `useCssElement`;
  - pin `lightningcss`;
  - `nativewind-env.d.ts`.

  Kudo odpowiedział: „we should not maintain the skill in the expo plugin … maybe you should maintain your own skills.”
  Lowder dodał: „convert the current Expo skill to a reference that points to your skills, so that you own the source of truth.”
- **PR [#174](https://github.com/expo/skills/pull/174)** (zamknięty jako zastąpiony przez #151). Agent Expo
  zdiagnozował 17 rozmów ENG-25794: błędy instalacji i natywne crashe Metro na SDK 54–57. Przyczyną był pin
  „deprecated third-party `react-native-css` nightly built for an Expo 54 preview” i stare API v5.
- **Co Expo zaleca w zamian:**
  - `expo-design-system` po zmianie mówi: „For Tailwind projects, keep tokens in `global.css` as CSS variables and follow
    the styling library's own setup guidance.” Wcześniej odsyłał do `expo-tailwind-setup`
    ([diff a8f0b6c](https://github.com/expo/skills/commit/a8f0b6c737fa915e4697f76ea6d9e427df9b19db)).
  - Domyślne audyty tego skilla zakładają „plain `StyleSheet`, `boxShadow` strings, one `src/theme` entry point”
    ([audit.md](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-design-system/references/audit.md)).
  - `expo-web-to-native` dla `className`: „`StyleSheet.create` or NativeWind”.
- **Pozostałości upstream:**
  - `expo-overview/SKILL.md` (l. 34) nadal wymienia nieistniejący `expo-tailwind-setup`;
  - oficjalny przykład `expo/examples/with-tailwindcss` na Expo 57 nadal pinuje `nativewind 5.0.0-preview.2`
    i `react-native-css 0.0.0-nightly.5ce6396`
    ([package.json](https://github.com/expo/examples/blob/master/with-tailwindcss/package.json)).

  Na żadnym z nich nie wolno się opierać.

Na Androidzie `performAndroidHapticsAsync` zamiast API `Vibrator`. Na iOS nie działa w Low Power Mode i przy aktywnej kamerze albo dyktowaniu, więc haptyka nie może nieść jedynej informacji. Preferować komponenty z wbudowaną haptyką (`Switch`, datetimepicker). Zaawansowane wzorce: Pulsar | [expo-haptics](https://docs.expo.dev/versions/latest/sdk/haptics/), [expo-native-ui](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-native-ui/SKILL.md) |

Paski systemowe: `expo-status-bar`, `expo-navigation-bar` (Android) | [expo-native-ui](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-native-ui/SKILL.md), [expo-ui](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-ui/SKILL.md), [system bars](https://docs.expo.dev/develop/user-interface/system-bars/) |

## 6. Co zrobić z `expo-tailwind-setup`

1. **Natychmiast, niezależnie od D7:** usunąć z preloadu builderów. Usunąć pin `5.0.0-preview.2` z
   `feature-builder-mobile-ui.md` (l. 71) i odwołania w `ux-ui-guidelines-mobile` (SKILL.md l. 201, `spacing-grid.md`,
   `typography.md`, `icons.md`). Kopia instaluje zestaw, który upstream uznał za wadliwy (§1), a jej API (`useCssElement`
   jako wymagany wrapper, l. 458) jest nieaktualne nawet dla v5 RC.
2. **Spike (1 sesja):** `create-expo-app` na SDK 58 + Uniwind Free + Expo Router.
   - Sprawdzić: dev build iOS/Android, `className` na `View`/`Text`/`Pressable`/`TextInput`, `expo-image` przez
     `withUniwind`, `dark:` + `Uniwind.setTheme`, `@theme` z fontem, FlashList + `recyclingKey`, Reanimated CSS transition
     na elemencie z `className`, `react-native-reusables` `Button`.
   - Równolegle ten sam zestaw z NativeWind `5.0.0-rc.1`, żeby porównać.
3. **Po decyzji D7:**
   - **Uniwind:** skasować `expo-tailwind-setup`. Do bootstrapu dodać `npx skills add uni-stack/uniwind` (albo przypiętą
     kopię skilla `uniwind` z adnotacją źródła i commitem). `references/styling-engine.md` opisuje tylko nasz kontrakt.
   - **NativeWind:** przemianować na `nativewind-setup` (zgodnie z A0.2 §9) i przepisać pod `5.0.0-rc.1` / stable według
     [release notes](https://github.com/nativewind/nativewind/releases/tag/5.0.0-rc.0). Wpisać do audytu świeżości
     z kryterium „SDK w release notes = SDK szablonu”. Obserwować pojawienie się oficjalnego skilla użytkowego NativeWind,
     do którego Expo zapowiada referencję ([#151](https://github.com/expo/skills/pull/151)).
