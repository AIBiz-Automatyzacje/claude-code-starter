# Reguły stacku: Expo / React Native

Reguły kodu aplikacji Expo (React Native, Expo Router, Supabase). Uzupełniają `coding-rules.md`; przy sprzeczności dla
kodu aplikacji wygrywa ten plik. Tu stoi tylko „nigdy / zawsze” — jak to zrobić, mówią skille `rn-expo-guidelines`,
`expo:*`, `ux-ui-guidelines-mobile`, `supabase-dev-guidelines`, `mobile-e2e-maestro`. `(hook)` — regułę sprawdza też
hook `mobile-anti-pattern-check.sh` po każdej turze; `[D7]` — brzmienie zależy od silnika stylowania.

## Prymitywy RN zamiast DOM i Web API

- Bez elementów HTML (`div`, `span`, `p`, `button`, `input`, `a`, `img`): `View`, `Text`, `Pressable`, `TextInput`,
  `Link` z `expo-router`, `Image` z `expo-image` — RN nie ma DOM, element HTML wywraca render. (hook)
- Każdy tekst stoi w `<Text>`; goły string w `View` to crash.
- Bez `window.*` i `document.*`; kod tylko dla webu trzymasz w pliku `.web.tsx` albo za `process.env.EXPO_OS === 'web'`. (hook)
- Bez `localStorage` i `sessionStorage`: sesja i sekrety → `expo-secure-store` (przez adapter, sekcja „Dane i sieć”),
  zwykły cache → `AsyncStorage`. (hook)
- Nawigacja tylko przez `expo-router` (`useRouter`, `usePathname`, `useLocalSearchParams`, `Link`); bez `react-router`,
  `useNavigate`, `useLocation`. (hook)
- Platformę rozpoznajesz przez `process.env.EXPO_OS` zamiast `Platform.OS` (martwa gałąź wypada z paczki); duży rozjazd
  platform — osobny plik `.ios.tsx` / `.android.tsx`.
- Nie zakładasz API przeglądarki ani Node w Hermesie (`AbortSignal.timeout`, `Buffer`, `crypto.subtle`, `Blob`
  z `fetch`) — bierzesz moduł Expo (`expo-crypto`) albo helper projektu. Limit czasu żądania daje helper
  z `AbortController` + `setTimeout` (z `clearTimeout` po odpowiedzi), nie `AbortSignal.timeout`.

## Konfiguracja, env i build

- Zmienne klienta tylko jako `process.env.EXPO_PUBLIC_*` czytane statycznie przez kropkę — destrukturyzacji
  i `process.env[...]` Expo nie podstawi; bez `import.meta.env`. (hook: `import.meta.env`)
- W `EXPO_PUBLIC_*` nie ma sekretów (klucz `service_role`, płatne klucze API): wartość trafia jawnym tekstem do paczki
  aplikacji; sekret żyje w Edge Function.
- Logika serwerowa idzie do Supabase Edge Functions, nie do Expo API Routes (`+api.ts`) — szablon nie hostuje serwera Expo.
- React Compiler jest włączony, gdy app config ma `experiments.reactCompiler: true` (osobna paczka nie jest potrzebna).
- Przy CNG (`ios/` i `android/` poza repo) nie edytujesz katalogów natywnych ręcznie: zmiana idzie przez config plugin
  w `app.json` / `app.config.ts`, bo `prebuild` ją nadpisze.
- W config pluginie nie ustawiasz uprawnienia na `false` (`cameraPermission: false`) — kasuje klucz `Info.plist`
  globalnie, także dodany przez inny plugin; po zmianie pluginów `npx expo prebuild --clean` i sprawdzenie
  `UsageDescription` w wyniku.
- `app.json` nie podstawia zmiennych środowiska: wymagany prop config pluginu ma placeholder podmieniany przed buildem,
  nie pustą wartość.
- `eas build`, `eas submit` i `eas update` uruchamiasz tylko na polecenie operatora — kosztują kredyty albo publikują
  aplikację użytkownikom.

## Zależności natywne

- Pakiet z zestawu SDK instalujesz przez `npx expo install` (wersja zgodna z SDK) i nie podbijasz go ręcznie — ta reguła
  ma pierwszeństwo przed „Wersje przypinasz dokładnie”. Wersję inną niż wskazuje SDK pinujesz dokładnie i dopisujesz
  do `expo.install.exclude`, żeby `expo install --check` i expo-doctor jej nie cofały.
- Jednostka, która dodaje paczkę z kodem natywnym albo zmienia plugin w app config, deklaruje rebuild dev-clienta —
  bez niego „Cannot find native module” to błąd środowiska, nie kodu.
- Wersje preview/RC silnika stylowania i jego zależności (`react-native-css`, `tailwindcss`, `@tailwindcss/postcss`,
  `lightningcss`) pinujesz dokładnie i w `overrides`; wersja nightly nie wchodzi do projektu. [D7]

## Stylowanie [D7]

- Kolor, odstęp i typografia pochodzą z tokenów `@theme` w `global.css`; klasę z planu przed użyciem sprawdzasz grepem
  w `@theme`, bo klasa bez tokenu to cichy no-op przy zielonym typechecku, linterze i testach. `tailwind.config.js`
  nie jest czytany.
- Bez dowolnych kolorów w klasach (`bg-[#hex]`) i bez klas sklejanych z fragmentów (`bg-${x}`) — kompilator ich nie
  widzi; wariant wybierasz z mapy pełnych nazw klas albo przez `cn()`.
- Ciemny motyw przez warianty `dark:` i API silnika (`Uniwind.setTheme` / `Appearance.setColorScheme`), nigdy przez
  `:root.dark` — na natywnych platformach nie działa. [D7]
- Komponent spoza RN core (`SafeAreaView` z safe-area-context, `expo-image`, Lottie, mapa) przyjmuje `className` dopiero
  po owinięciu (`withUniwind` / `styled`) — bez niego `className` jest cichym no-op. [D7]
- Prop koloru spoza `style` (`ActivityIndicator.color`, `Switch.trackColor`, kolor ikony) bierze wartość z tokenu przez
  mechanizm silnika (`accent-*` / `styled` z mapowaniem propsa) albo stałą z modułu tokenów, nie z literału hex. [D7]
- Cień przez `boxShadow`, nie `shadow*` / `elevation` (jedno API na obie platformy).
- Tylko NativeWind v5: `<TextInput>` stylujesz przez `style`, nie `className` (crash widoczny tylko na urządzeniu);
  rozmiary display piszesz inline (`text-[48px] leading-[48px]`), bo sufiksy `--text-X--line-height` w `@theme` są
  ignorowane; bez procentowych `translate-*` (centrujesz flexboxem albo stałym przesunięciem z makiety); `font-variant`
  i style hostów natywnych (`VideoView`, `Animated.View`, Skia) idą przez `style`. [D7]

## Układ, listy, obrazy, klawiatura, dostępność

- Safe area z `react-native-safe-area-context` (`SafeAreaView` albo `useSafeAreaInsets`), nigdy `SafeAreaView`
  z `react-native`. Na ekranie stosu przewijany kontener stoi pierwszy, z `contentInsetAdjustmentBehavior="automatic"`.
- Lista długa albo o nieznanej długości to `FlashList` albo `FlatList`, nigdy `.map()` w `ScrollView`; `List` z `@expo/ui`
  tylko dla krótkich list ustawień, bo nie wirtualizuje.
- Stan wiersza `FlashList` trzymasz w `useRecyclingState`, nie w `useState` — recyklowana komórka przenosi stan na
  inny element; wiersz listy wirtualizowanej nie dostaje animacji `entering`.
- Obraz przez `expo-image`; w liście wirtualizowanej z `recyclingKey`, inaczej mignie poprzednie źródło. Bez
  `ImageBackground` (zdeprecjonowany): `View` + obraz pozycjonowany absolutnie.
- Formularz z klawiaturą stoi w `KeyboardAwareScrollView` z `react-native-keyboard-controller`, z
  `keyboardShouldPersistTaps="handled"`; główna akcja nie chowa się pod klawiaturą; bez `Keyboard.addListener` z ręczną
  animacją.
- Zanim napiszesz arkusz, picker, slider, przełącznik albo menu, sprawdzasz odpowiednik w `@expo/ui` — renderuje
  natywną kontrolkę.
- Nie wyłączasz `allowFontScaling`; `maxFontSizeMultiplier` stawiasz tylko tam, gdzie układ nie ma wyjścia (pasek kart).
- Element interaktywny bez widocznego tekstu (ikona, obraz) ma `role` / `accessibilityRole` i `accessibilityLabel`.

## Nawigacja i cykl życia ekranu (Expo Router)

- Przekierowanie po logowaniu i rejestracji wynika z efektu na stanie sesji (guard w layoucie), nie z `router.replace`
  po `await` w handlerze — przy sesji, która jeszcze nie dotarła, powstaje pętla przekierowań.
- Autoryzację trasy niesie layout grupy: przeniesienie trasy do innej grupy albo stosu wymaga przeglądu guardów.
- Ekran pod stosem zostaje zamontowany: dane po powrocie odświeżasz w `useFocusEffect`, hook danych wystawia `refetch`
  także w stanie `ready`, a odświeżenie pokazuje ostatni wynik zamiast pustego stanu.
- `visible` natywnego `<Modal>` zależy od jawnie potwierdzonej wartości, nigdy od negacji stanu async (`!isGranted`
  obejmuje też `null`) — osierocony modal zjada dotyk całego ekranu.
- Nawigację po zamknięciu modala robisz w `onDismiss`; przed `router.push` zamykasz stanem wszystkie przezroczyste modale.
- Parametry trasy i deep linku (`useLocalSearchParams`, URL schematu aplikacji) parsujesz schematem Zod jak każde wejście
  z zewnątrz; akcja z deep linku nie zakłada, że użytkownik jest już członkiem zasobu.
- Testów nie kładziesz w `app/` — każdy plik tam jest trasą; testy tras idą do `__tests__/` (wyjątek od „Testy leżą
  obok plików źródłowych”).

## Uprawnienia

- Status uprawnienia `null` znaczy „nie wiem” i nie pokazuje żadnego UI; sprawdzenie bez promptu robisz
  `get*PermissionsAsync`, a błąd przejściowy (np. timeout lokalizacji) to nie `denied`.
- O uprawnienie prosisz przy akcji, która go potrzebuje, nie na starcie; odmowa ma ścieżkę do ustawień systemu.

## Dane i sieć

- Sesję Supabase trzymasz przez adapter z `supabase-dev-guidelines` (klucz w `expo-secure-store`, zaszyfrowana wartość
  w `AsyncStorage`), z `detectSessionInUrl: false` — sam SecureStore nie przyjmie wartości powyżej 2048 B, a jawny
  `AsyncStorage` trzyma token otwartym tekstem.
- Upload binarki do Storage idzie przez `ArrayBuffer` / `Uint8Array` (z base64), nigdy przez `Blob` z `fetch().blob()` —
  RN wysyła wtedy plik 0 B z odpowiedzią 200; sukces potwierdzasz rozmiarem obiektu > 0.
- Stałe i typy importujesz z modułu-liścia, nie z barrela, który ciągnie klienta Supabase albo moduły natywne — barrel
  wywraca loader testów.
- Z TanStack Query podpinasz `focusManager` do `AppState` i `onlineManager` do NetInfo — RN nie ma zdarzeń okna, więc
  bez tego nie ma odświeżenia po powrocie z tła ani po odzyskaniu sieci.
- Brak sieci to stan normalny: ekran pokazuje ostatnie dane z informacją o błędzie, a zapis bez sieci kończy się jawnym
  błędem albo kolejką, nie spinnerem bez końca.

## Animacje i haptyka

- Animowana lista to `Animated.FlatList<T>` z Reanimated, nie `createAnimatedComponent(FlatList)` — ten gubi generyk.
- `SharedValue` nie trafia do zależności efektu; tylko prymitywy.
- Krzywą podajesz helperem `cubicBezier`, nie surowym stringiem; do stylów Reanimated nie przekazujesz `PlatformColor`.
- Animacja respektuje ograniczenie ruchu (`useReducedMotion`, `ReduceMotion.System`).
- Haptyka komunikuje wynik (`notificationAsync` w kodzie wywołującym, po zatwierdzeniu), atomy UI nie wołają `Haptics`;
  haptyka nigdy nie niesie jedynej informacji (iOS wyłącza ją m.in. w trybie niskiego zużycia energii).

## Testy jednostkowe (jest-expo + React Native Testing Library)

- Komponent testujesz przez `@testing-library/react-native` (zapytania po roli i tekście, `testID` na końcu); asercja
  dotyczy zachowania, nigdy `className` ani snapshotu stylów — wygląd sprawdza smoke na urządzeniu.
- Nawigację testujesz przez `renderRouter` z `expo-router/testing-library`, z `await` na `renderRouter` i metodach
  `testRouter` (od SDK 58 są asynchroniczne).
- Moduły natywne (Reanimated, worklets, kamera, Skia, Sentry, powiadomienia) mają globalne atrapy w setupie runnera; nowe
  API dopisujesz do globalnej atrapy, a lokalny `jest.mock` tych modułów jest zakazany — pusta lokalna atrapa wybucha,
  gdy dziecko zacznie animować.
- Komponent, który pośrednio wpina transport realtime, ma w teście stub na granicy hooka transportu.
- Po `jest.useFakeTimers()` z renderem odmontowujesz drzewo przed `jest.useRealTimers()` — inaczej timery wyciekają do
  losowego następnego pliku.
- Preset testów raportuje jedną platformę: kod z gałęzią `EXPO_OS` / `Platform.OS` ma test drugiej gałęzi albo punkt
  w smoke'u operatora.

   - Stryker: `@stryker-mutator/vitest-runner` → `@stryker-mutator/jest-runner`;
   - bez size-limit.
3. **`scripts/bramki`.** `bramkaVitestTypecheck` uruchamia się tylko przy wykrytym Vitest (`narzedzia.mjs`), więc

## 5. `learned-patterns.md` mobile

**Jak web ładuje wiedzę (grep w `.claude/`):**
- Reguł nie ma w `.claude/rules/`. Indeks `docs/learned-patterns.md` generuje `node .claude/scripts/wiedza/wiedza.mjs
  indeks --zapisz` z pól frontmattera `docs/solutions/` (`klasa`, `regula`, `paths`, `waga`, `szczebel`;
  `scripts/wiedza/indeks.mjs`, `MAKS_ZAWSZE = 5`, `MAKS_INDEKS_ZN = 40000`).
- Kto czyta indeks:
  - `dev-plan` czyta go w całości (SKILL.md l.104);
  - buildery dostają od plannera wycinek per pliki (`wiedza.mjs wycinek --pliki`);
  - reviewerzy dostają ten sam wycinek w dossier (`scripts/dossier/wiedza-blok.mjs`);
  - fix autopilota bierze wycinek dla poprawianych plików (`dev-autopilot-wf.js` l.675).
- Commit indeksu robią compound, complete i dev-pr. Linię w `CLAUDE.md`, która wskazuje indeks, dopisuje operator.
- Konwersja starego formatu: `/dev-compound-refresh --konwersja` (`wiedza.mjs konwersja przygotuj|zastosuj`). Każda
  reguła potrzebuje pliku solution. Stary plik idzie do `docs/archiwum/learned-patterns-<data>.md`, a odrzuty do
  osobnego pliku do decyzji operatora.

**Decyzja dla szablonu:** `workspace-template-mobile/.claude/rules/learned-patterns.md` (2 reguły Maestro) **nie trafia
do nakładki ani do `docs/learned-patterns.md`**. Powody:
1. Indeks jest plikiem projektu, a `sync-template` przenosi tylko `.claude/` (SKILL.md l.17–19). Szablon nie może
   dostarczyć `docs/learned-patterns.md`.
2. Format indeksu wymaga pliku solution dla każdej reguły. Reguły szablonu pochodzą z `gramywpadla` i ich solutions
   nie ma w nowym projekcie.
3. Treść jest już tam, gdzie powinna być wiedza szablonu (A0.6 #59, #60 „tak”). Granica natywnych powierzchni
   → `mobile-e2e-maestro` §Granica (l.188) + `dev-plan` l.450, czyli w nowym układzie slot `plan-e2e.md` i tester.
   GraalJS w `runScript` → `mobile-e2e-maestro` l.204.

Poprawka planu: w IU-2.8 zamiast „`learned-patterns` Maestro → `docs/learned-patterns.md` (format weba)” wpisać:
„reguły Maestro z `rules/learned-patterns.md` → `mobile-e2e-maestro` + `plan-e2e.md` (już są); plik poza nakładką;
projekty konwertują własny plik przez `/dev-compound-refresh --konwersja`”.

**Ryzyko dla projektów (Etap 4):**
- Oba projekty mają `.claude/rules/learned-patterns.md` w `.claude/.template-manifest` (l.21) i własną treść:
  `gramywpadla` 49 reguł, `Nawykometr` 7.
- Przy pierwszym syncu wariantu z nakładki `sync-template.sh` (l.163–180) zaklasyfikuje plik jako REMOVE. Plik
  zostanie usunięty z backupem w `.claude/.backups/<ts>/`.
- Konwersja czyta `.claude/rules/learned-patterns.md`, więc po syncu nie znajdzie nic do przeniesienia. Narzędzie
  konwersji (`scripts/wiedza/`) przychodzi dopiero z tym samym syncem.
- Kolejność dla pilota:
  1. dry-run;
  2. sync;
  3. przywrócenie pliku z `.claude/.backups/<ts>/`;
  4. `/dev-compound-refresh --konwersja`;
  5. decyzja operatora o odrzutach (w `gramywpadla` część reguł nie ma solution, A0.6 #3).
- Alternatywa w rdzeniu (pyt. 6): `sync-template.sh` nie usuwa pliku `.claude/rules/learned-patterns.md`, jeśli różni
  się od ostatniej wersji szablonu, i wypisuje wskazówkę o konwersji.
