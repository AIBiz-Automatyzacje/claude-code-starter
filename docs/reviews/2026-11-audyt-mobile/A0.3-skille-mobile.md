## 1. Podsumowanie

1. **Trzy wspólne skille (`security`, `sentry-integration`, `supabase-dev-guidelines`) są w mobile starą treścią weba z doklejonymi
   akapitami mobilnymi.** Web od 2026-09-01 przebudował je strukturalnie (security: reguły kodu w `SKILL.md` + `resources/protokol-audytu.md`;
   supabase: `SKILL.md` 80 linii + `resources/klient-i-przeglad.md`; sentry: zasady z uzasadnieniem, oczekiwane odmowy poza Sentry,
   użytkownik tylko przez `id`) i poprawił merytorycznie (REVOKE EXECUTE dla `SECURITY DEFINER`, `withSupabase` we wszystkich przykładach
   Edge Functions, `--lang typescript`, publishable/secret keys). Treść naprawdę mobilna to ok. 15–20% każdego z nich i daje się wyjąć
   do jednego pliku stackowego na skill (§5). Rekomendacja: **rdzeń = wersja web (zneutralizowana) + `references/stack.md`** dla wszystkich trzech.
2. **Ustalenia świeżości: 11 × P1, 34 × P2** (§3). Najgroźniejsze dla buildera: Realtime re-subscribe rzuca wyjątek, niekompletna
   instalacja klienta Supabase, brak `getSentryExpoConfig` w `metro.config.js` (sourcemapy/Debug ID), `expoRouterIntegration` niedostępne
   w wersji SDK, którą instaluje `expo install` na SDK 57, Stripe Checkout bez ostrzeżenia o zasadach App Store / Play, sprzeczne opisy
   DOMPurify w RN, `AndroidHaptics.GestureStart` (nie istnieje), reguła `KeyboardAvoidingView behavior="height"` na Androidzie. Dla testera:
   zakaz testowania na dev-clientcie (l.248 `mobile-e2e-maestro`) — sprzeczny z dokumentacją Maestro i z całym harnessem.
3. **Alert poza zakresem mobile:** Supabase CLI 3.0.0 (2026-11-02) wymaga `--yes` dla zmian na hostowanym projekcie i deprecjonuje `--db-url`
   na rzecz `--remote`. Webowy db-sync (`dev-autopilot-wf.js` l.597) woła `supabase db push --db-url … --include-all` nieinteraktywnie —
   po aktualizacji CLI u operatora przestanie działać (do potwierdzenia na v3, §7 pyt. 1).
4. **`mobile-e2e-maestro`** zostaje jako plik nakładki, ale sekcja integracji z testerem (l.176–186) opisuje kontrakt sprzed P14
   (tylko `Weryfikacja:`, pass/fail, bez przyczyny SKIP). Pod nowy kontrakt trzeba dopisać mapowanie sytuacji Maestro na przyczyny
   `ksiegowanie.mjs`, dowód (exit code `$?` + zrzuty pod `--test-output-dir` w folderze zadania — Maestro ≥ 2.8 odrzuca ścieżki zrzutów
   spoza katalogu artefaktów) i odczyt scenariuszy przez `e2e.mjs scenariusze`.
5. **`e2e-setup` da się wchłonąć** w wariant Maestro `weryfikacja-setup` + nakładkowy `templates/e2e-env/README.md` + adapter E2E (§6).
   Część bazodanowa (osobny projekt, pooler, marker, seedy przez `psql`, konto testowe) już jest w webowym README. Do przeniesienia zostaje
   wiedza o dev-clientcie i Maestro (pułapki 6–8, 10–11, para `EXPO_PUBLIC_E2E_TEST_USER_*`, build z `CODE_SIGN_IDENTITY="-"`, canary).
6. **`ux-ui-guidelines-mobile`** jest świeży w szkielecie (FlashList v2, formSheet, `@expo/ui`, gorhom potwierdzone), ale snippety mają
   2 × P1 i 10 × P2 (Reanimated 4 `scheduleOnRN`, RNGH 3 hooki, CSS animations, SDK 58 / iOS 27). Decyzja: zostaw + aktualizuj punktowo,
   razem z A0.4 (NativeWind v5 nadal RC) i A0.2 (nazwy `expo:` w „Powiązane Skills”).
7. **Kierunek odwrotny — web ma błędy, które mobile ma dobrze albo które wyszły przy okazji:** limit Realtime „500 kanałów na połączenie”
   (web: `realtime.md:368`; faktycznie 100), `@sentry/deno` 11 ma już `denoServeIntegration` i wymaga Deno ≥ 2.8.3 (web twierdzi, że
   integracji nie ma), komentarz `major_version` w `cli-guide` (mobile lepszy). Lista w §4.4.

### 4.1 `security`

Co web zrobił od 2026-09-01, czego mobile nie ma:
- podział: `SKILL.md` = reguły dla piszącego kod (z powodem przy każdej regule), audyt przeniesiony do `resources/protokol-audytu.md`
